# Пирамида `core/ui`

Разбор каждого файла в `core/ui`. Код не менялся.

Правило, по которому смотрел: нижний кирпич умеет одно дело и не знает, кто его вызовет. Верхний модуль только собирает кирпичи и задаёт им числа, подписи и колбэки. Он не лезет в чужой `UiPaint`, `UiFlex`, `UiField` и не рисует `UiPrimitive` сам.

Слои, как они должны стоять:

1. Запись кадра. Прямоугольник, глиф, иконка, картинка, ножницы. Ни одного имени виджета.
2. Узел. Рождение, родитель, показ, имя, бокс после вёрстки.
3. Вёрстка. Yoga и только Yoga.
4. Ввод. Попадание, фокус, жест. Фазы зовут хуки, сами виджеты не называют.
5. Виджет. Один виджет — один файл. Ставит свои компоненты. Рисунок отдаёт записи кадра.
6. Сборка. Инспектор, цвет, календарь, док, файл. Только вызывает виджеты.

Сейчас почти каждый заголовок виджета тянет `State.hpp`, а `State.hpp` тянет вёрстку, текст, примитив, бинарный формат и шрифт. Из-за этого кнопка видит меню, поле видит окно, а дерево видит папку.

Ниже сначала общие разрывы, потом каждый файл.

## Общие разрывы

### 1. `UiState` — общий мешок, а не узел

`core/ui/State.hpp` (404 строки) держит сразу всё: мир Flecs, Yoga, боксы, родителей, фокус, захват, меню, поле, команды, шрифт, анимацию, буфер вставки, шину дропа, загрузчики bin, хуки ввода, хуки рисования, тему, метрики, грязь вёрстки.

Фасады есть (`uiSetField`, `uiSetMenu`, `uiNotifyLayoutDirty`), но поля публичные. Любой `.cpp` пишет `s.menu`, `s.field`, `s.capture`, `s.layoutDirty`, `s.visualDirty` напрямую. Поэтому модули не разговаривают через функции, они делят одну структуру.

Каждый виджет включает этот заголовок. Мелкий кирпич из-за этого невозможен: чтобы поставить подпись, файл видит команды, bin и атлас.

### 2. Ядро само включает все виджеты

`core/ui/Node.cpp` включает `widget/Widgets.hpp`. Конструктор `UiState` вызывает `uiWidgetsInit`. Рождение узла не может собраться без кнопки, меню, дока, цвета и календаря.

`core/ui/widget/Widgets.cpp` — единственное место, которому положено знать все виджеты. Оно лежит внутри слоя виджетов и его тянет слой узла. Реестр должен стоять над виджетами, а узел его не видит.

Хуки при этом с потолком, лишнее молча выбрасывается:

| Стол | Потолок | Уже занято |
| :--- | :--- | :--- |
| `UiDrawHooks::fn` | 4 | рисунок, который перехватывает узел целиком |
| `UiDrawHooks::decor` | 8 | number, field, curve, gradient, slider, check |
| `UiOverlayHooks` | 4 | полоса прокрутки, док |
| `UiInputHooks` | 12 | 11 хуков в `uiWidgetsInit`, место на один виджет |
| `valueFn` | 4 | слушатели числа |
| `bootFn` / `beforeFn` / `clearFn` | 4 | старт и очистка |
| `gBoot` в `Node.cpp` | 4 | процессная `static`-таблица, не поле `UiState` |

`gBoot` живёт в анонимном пространстве `Node.cpp`. Состояние кадра должно лежать на `UiState`.

### 3. Виджеты рисуют сами и правят чужие компоненты

Запись кадра умеет прямоугольник, рампу и глиф. Поверх этого каждый виджет пишет `UiPrimitive*` в своём decor/overlay:

- `Field.cpp` — `uiFieldDecor`
- `Number.cpp` — `uiNumberDecor`
- `Slider.cpp` — `uiSliderDecor`
- `Button.cpp` — `uiCheckDecor`
- `Curve.cpp`, `Gradient.cpp`
- `Scroll.cpp` — `uiScrollOverlay`
- `kit/Color.cpp` — `colorCustomDraw`
- `Docking.cpp` — `dockOverlayDraw`
- `PrimitiveBatch.cpp` сам ещё и панель, и текст, и `UiImage`

Верхние модули вдобавок лезут внутрь нижних: `try_get_mut<UiPaint>`, `try_get_mut<UiFlex>`, `try_get_mut<UiField>`, `try_get_mut<UiSplitter>`. Это `PropGrid`, `Color`, `Calendar`, `Breadcrumbs`, `Number`, `Docking`, `Tabs`, `Thumb`.

Кирпич «число» должен принимать `uiRangeSet`. Сейчас сосед сам пишет текст поля.

### 4. Один экземпляр на весь интерфейс

Эти штуки лежат на `world.ensure<...>()`, второй раз их не поставить:

- `UiColorPickerComponent` — одно окно цвета, слоты `colorNum[7]`, `colorRgb[3]`, `colorHsv[3]`
- `UiCalendarComponent` — одна сетка, `calDay[42]`
- `UiDock` — одна панель дока
- `UiDragDrop` — один жест на весь кадр
- `UiMenuMetrics` — одно открытое меню
- `UiFieldUndo::snap[8]` — одна история на все поля

`UiPropFilterBar::button[12]` и `section[12]` — потолок секций инспектора. Десятый фильтр и десятимиллионный должны идти через один рециклер, как строки виртуального списка.

### 5. Формат документа знает каждый виджет

`BinNode` в `UiBin.hpp` — 204 байта и сразу flex, краска, фильтр поля, чекбокс, слайдер (`minV`/`maxV`/`value`), стиль текста, тень. Роли (`uiBinRole`, `kBinSlot*`) как раз для того, чтобы формат роли не знал. Поля роли всё равно вшиты в общую запись.

`kUiImportItemCap = 8` режет список пунктов меню при импорте.

### 6. Тема и метрики перечисляют продукты

`UiToken` и `UiLook` знают Button, Field, Menu, Slider, Check, Scroll, Chrome, Status. Это палитра, ей можно знать роли краски.

`UiMetrics` уже не палитра. Там высота кнопки и поля, и рядом `ghostW` (призрак перетаскивания), `tuneW`/`tuneH` (панель настройки), `iconMin`/`iconMax` (сетка файлов). Размеры продукта сидят в кирпиче, который видят все.

`UiIcon`: `Document = 2` и `Maximize = 2`. Окно и файл делят один глиф. `Folder` — файловый смысл в общей таблице, и дерево ниже рисует его каждой строке.

## Уже кирпичи

Эти файлы делают одно дело. Их не надо растаскивать, на них надо опереть остальное.

| Файл | Дело |
| :--- | :--- |
| `Geometry.hpp` | бокс, попадание в бокс, ножницы |
| `Flex.hpp` | режимы Yoga, без виджетов |
| `FlexAttr.hpp`, `FlexAttr.cpp` | записать атрибут flex |
| `Hover.hpp`, `Hover.cpp` | подсветка узла с тегом `UiHoverable` |
| `Focus.cpp` | фокус и Tab по `UiFocusable` |
| `Hit.cpp` | `hitTest` только по боксу и ножницам предков |
| `Input.cpp` | насос фаз. Виджеты зовёт через хуки, по имени не знает |
| `LayoutBridge.hpp`, `LayoutBridge.cpp` | Yoga, `cacheBox`, `uiLayout` |
| `Motion.cpp` | цвет и раскрытие высоты |
| `Label.hpp`, `Label.cpp` | панель плюс текст, клик пропускает |
| `Tip.hpp`, `Tip.cpp` | одна подсказка: поставить, показать у точки |
| `Tabs.hpp`, `Tabs.cpp` | пометить активную вкладку токеном |
| `Rubberband.hpp`, `Rubberband.cpp` | рамка выделения по детям хозяина |
| `Splitter.hpp`, `Splitter.cpp` | хват и два соседа. Чужие виджеты не включает |
| `Scroll.hpp`, `Scroll.cpp` | прокрутка и бегунок. Дело одно, рисует бегунок сам (см. разрыв 3) |
| `Panel.hpp`, `Panel.cpp` | заливка прямоугольника. И фабрика узла, и `uiEmitPanel` |

Мелочи, которые в этих кирпичах всё же чужие:

- `Hover.cpp` сам гасит альфу у `disabled` и поднимает слишком слабую альфу до 0.28. Это правило кнопки, не подсветки.
- `Tabs.cpp` идёт по всем узлам кадра (`id` от 1 до `count`), хотя дети полосы уже известны родителю.
- `Tip.cpp` пишет обводку каналами `muted`, мимо токена.
- `Hit.cpp` и `Input.cpp` чистые. Фазы `Menu` и `Chrome` названы в `State.hpp` (`UiInputPhase`), а в коде это `kUiPhase4` и `kUiPhase5`. Имя продукта сидит в насосе ввода.

## Запись кадра и картинка

### `Primitive.hpp`

Запись `UiPrimitive` (80 байт) — правильный кирпич кадра. В том же файле номера кучи Vulkan: слот 48, атлас 661, фото 662. Любой, кто считает прямоугольник, видит дескрипторы. Номера слотов живут в `core/rhi/DescriptorSlots.hpp`. Здесь достаточно флага «глиф / фото / рампа» и байта индекса фото.

### `PrimitiveBatch.hpp`, `PrimitiveBatch.cpp` (499)

Должен сложить готовые записи в порядке дерева и отрезать по ножницам.

Сейчас `uiEmit` ещё:

- строит порядок детей (это дело узла);
- красит hover (`uiHoverTint`);
- рисует подложку иконки, если `paint->plate`;
- узнаёт `UiImage` и зовёт `uiEmitSprite`;
- зовёт `uiEmitPanel` и `uiEmitTextNode`;
- бежит по decor и overlay.

`UiImage` объявлен в `UiPhoto.hpp`. Пакет кадра зависит от загрузчика фото и от панели. Панель по конституции — слой виджета, пакет — слой ниже. Включение `Panel.hpp` из `PrimitiveBatch.cpp` идёт вверх.

`putFloat` продублирован в `Text.cpp`.

Обход пустого клипа уже есть (строки про `ancestor.w < 0.5f`). Это оставить.

### `Text.hpp`, `Text.cpp` (616)

Одно дело: измерить, завернуть, выпустить глифы. По объёму это весь текстовый стек, и он не включает виджеты. Так и должно быть.

Чужое внутри:

- `UiText::ownRun` — тайный выключатель «это поле, общий проход молчит». Поле и холст (`Canvas.cpp`, `UiWindowBridge.cpp`) договариваются через этот байт. Признак «глифы рисует хозяин» должен быть тегом узла, который ставит поле, а текст про него не думает.
- `textInk` сам осветляет горячий текст на 0.08. Это снова hover, не набор глифов.
- CSS-регистр, табы, тень, подчёркивание и масштаб в одном проходе. Их можно оставить в этом кирпиче, пока никто снаружи не повторяет перенос.

`Typography.hpp` — метрики глифа и `UiText`. Кирпич. `kUiLineCap = 8` режет число строк одного блока.

### `Font.hpp`, `Font.cpp`

Атлас: FreeType и заливка GPU в одном файле. Заголовок включает `rhi/Device.hpp`, `GpuImage.hpp`, `DescriptorHeap.hpp`. Измерение глифа и загрузка картинки — два кирпича. Виджету нужна только `UiGlyphMetric`.

### `UiPhoto.hpp`, `UiPhoto.cpp`

Три дела в одном:

- компонент `UiImage` (кадр, миникарта, вид);
- `PhotoMeta` и лимит `kPhotoFrameCap = 16`;
- `uiPhotoLoad` через `UiRenderer`, `Device`, кучу.

`Image.hpp` включает `UiPhoto.hpp`, поэтому иконка на кнопке видит устройство Vulkan. Компонент картинки должен лежать рядом с примитивом. Загрузка файла — отдельно, её зовёт холст.

### `rhi/UiRenderer.hpp`, `rhi/UiRenderer.cpp`

Запись командного буфера UI. Слой правильный: Vulkan, слот примитивов, без виджетов. Оставить кирпичом. Холст не должен тащить его в каждый виджет через `State.hpp` (сейчас не тащит напрямую, тащит `Canvas.hpp`).

### `ui.slang`

Шейдер кадра. Знает флаги примитива (глиф, иконка, колесо, рампа, фото). Это низ кирпича. Виджеты его не включают. Не трогать, пока рисунок остаётся данными `UiPrimitive`.

## Узел, документ, холст

### `Node.cpp` (874)

Должен: создать узел, назвать, показать, перенести, положить бокс.

Сейчас здесь же:

- `uiWidgetsInit` из конструктора `UiState`;
- шина дропа `uiDragBegin` / `uiDragEnd` (дело `DragDrop`);
- `uiRestyle` по всей краске;
- `uiDumpLayout` и подписи для отладки;
- `uiVirtualSetShown`;
- `uiPaintRgb` — прямой RGB мимо токена;
- `uiShowOnly` пробегает каждый узел кадра, а не детей родителя;
- `uiFindName` / `uiBindName`. Имя нужно сборке один раз. Крошки и поле зовут его в работе виджета;
- `gBoot` на процесс.

`spawn` ставит и Yoga, и Flecs, и `UiPaint`. Это и есть узел. Вёрстку и краску он хранит, не интерпретирует.

### `UiBin.hpp`, `UiBin.cpp`

Загрузка бинарного дерева. Роли и `uiSpawnDescribed` — правильный шов: неизвестную роль забирает хук.

Ломает шов сама запись `BinNode`: фильтр, чек, значение слайдера, выравнивание текста. Импорт меню режет пункты восьмёркой (`fillBag`, `kUiImportItemCap`).

`uiBinBuiltin` регистрирует только `"hidden"`. Остальные роли регистрируют виджеты сами, и это правильно. Вызов `uiBinBuiltin` сидит в `Widgets.cpp`, то есть документ без реестра виджетов пустой.

### `Json.cpp`

Кладёт дерево из JSON через `io/JsonCursor.hpp`. Второго парсера нет, это хорошо.

Файл всё равно знает `BinNode` целиком (`flexToBin`) и поэтому знает поля всех виджетов. Импорт должен собирать flex и краску, а роль отдавать тем же хукам, что bin.

### `Canvas.hpp`, `Canvas.cpp`

Комментарий верный: координатор кадра. Вызов вёрстки, ввода, движения и пакета — его дело.

В том же типе:

- `UiRenderer` и `Swapchain`;
- `photoMeta[kPhotoSlots]` и `canvasLoadPhoto`;
- шрифт;
- `canvasAddCommand` (меню);
- `canvasTakeWindowOps`, `canvasTakeClip`, `canvasChrome`;
- `canvasMaskScene` — глушит ввод 3D-сцены.

Холст стал фасадом продукта. Окно и сцена должны спрашивать узкие функции (`uiWindowTakeOps`), не жить в типе холста. Фото и шрифт — ресурсы кадра, их можно оставить рядом с рендерером, не в API команд меню.

### `UiWindowBridge.hpp`, `UiWindowBridge.cpp`

Четыре разные двери в одном файле: кнопки окна, буфер обмена, метрики заголовка, маска ввода сцены. Маска смотрит `ownRun` у текста в фокусе. Мост окна знает, что где-то есть сцена и поле.

Оставить здесь только флаги `WindowOps` и клип. Маска сцены — дело хоста, который уже знает и UI, и камеру.

### `Domain.hpp`

Лежит в `core/ui`, а тело `uiClearDomain` — в `core/files/Files.cpp`.

`UiHostNote` — флаги `tool`, `color`, `file`. Это переключатель продуктов. `UiPick` — имя выбранного объекта. Ни то, ни другое не кирпич интерфейса. Им место рядом с хостом и файлами. Пока заголовок в `core/ui`, шелл, HUD и тесты включают UI, чтобы поставить «это файлы».

### `Command.hpp`, `Command.cpp`

Имя говорит «команда». Файл делает строки меню: `uiMenuRow`, `uiMenuRowBind`, высота из `uiMenuMetrics`, краска и flex строки.

Команда — запись «имя, функция, пользователь». Строка меню — виджет `Menu`. Сейчас оба живут в `Command.cpp`, а `Menu.hpp` включает `Command.hpp`, чтобы видеть `UiMenuCmd`.

### `Popover.hpp`, `Popover.cpp`

Функция одна: поставить панель у якоря. Внутри она пишет `s.menuOpen` и `uiMenuMetrics(s).opened`. Поповер не бывает без меню. Якорь ищется через два `parentOf` вверх — это полоса меню, не общий попап.

Общий попап знает панель, якорь, ширину и высоту. Кто открыт — решает меню.

### `Interaction.hpp`

Сюда свалено, потому что это включает `State.hpp`:

- теги `UiHovered`, `UiFocused`, `UiFocusable`, `UiCapture`, `UiTextInput`, `UiPass`;
- колбэки клика, драга, колеса, редактирования;
- `UiCommand`;
- `UiDrop` / `UiDropTarget`;
- `WindowOps`;
- `UiName`.

Теги узла — кирпич узла. Колбэк — кирпич жеста. Команда — свой файл (и он уже есть, но тип лежит здесь). Окно — `UiWindowBridge`. Имя — узел.

`UiTab` тоже здесь, хотя вкладки — виджет.

## Виджеты, которые делают несколько работ

### `Button.hpp`, `Button.cpp` (348)

Один файл:

- кнопка с подписью (`uiButton`);
- кнопка-иконка (`uiIconBtn`) и кнопка-фото (`uiSlotBtn`);
- чекбокс и группа (`uiCheck`, `uiCheckPress`, `uiCheckOn`);
- рисунок галочки `uiCheckDecor`;
- три роли bin: button, check, close.

Кнопка ставит `UiAction` и краску токена. Чек — компонент `UiCheck` и свой рисунок. Иконка — кирпич `Image`. Закрытие окна — хром, не кнопка.

`Button.cpp` включает `Image.hpp`, `PrimitiveBatch.hpp`, `Panel.hpp`, `Text.hpp`.

### `Field.hpp`, `Field.cpp` (919), `TextEdit.cpp` (478)

Поля и редактор разрезаны по файлам, но заголовок один — `Field.hpp`. У `TextEdit.cpp` своего заголовка нет. Снаружи это один модуль.

Внутри:

- хранение байт, каретка, выделение, пароль, лимит;
- фильтры email / url / tel и `fieldProblem`;
- поиск `uiSearchField` и `uiBindSearch` через `uiFindName`;
- отмена на 8 снимков на весь кадр;
- команды cut/copy/paste/all/wipe;
- жест и клавиши;
- decor, который сам выпускает глифы (`ownRun`).

Каретка и вставка — кирпич редактора текста. Фильтр — правило поверх редактора, его задаёт сборка. Поиск — поле плюс иконка, не отдельный тип внутри поля. История отмены — на поле, не `snap[8]` на мир.

`Number.cpp` вызывает `uiSetFieldText` и `uiText` у того же узла. Ползунок и спин крутят байты поля, потому что число не умеет показать себя само.

### `Number.hpp`, `Number.cpp` и `Slider.hpp`, `Slider.cpp`

`UiRange` живёт в `Number.hpp`. `Slider.hpp` включает `Number.hpp`. Полоска не может существовать без числового поля.

Общий кирпич — диапазон: значение, минимум, максимум, шаг, колбэк. Число рисует его текстом. Слайдер рисует его заливкой. Спин — кнопками. Сейчас `dragSpin` в числе сам форматирует `snprintf("%.3f")` и зовёт всех `s.valueFn` (потолок 4).

Оба decor пишут примитивы.

### `Menu.hpp`, `Menu.cpp` (609)

Один файл:

- всплывающее меню и flyout;
- полоса `UiMenuBar`;
- кнопка, открывающая меню;
- выпадающий список `UiChoice` (подпись, ширина, bin-роль choice);
- ввод, закрытие, анимация `UiMenuSlide`;
- стиль метрик.

Список выбора — кнопка плюс меню. Ему не нужна вторая машина внутри `Menu.cpp`. Метрики открытого меню лежат на мире (`UiMenuMetrics`), поэтому второе меню делит `opened` и `flyout` с первым.

Строки меню собирает ещё и `Command.cpp`. Два строителя одной строки.

### `Fold.hpp`, `Fold.cpp`

Имя файла — секция. В нём же:

- компонент `UiTree` (body, clip, open, full);
- `uiTreeRow` — строка дерева;
- `uiFoldBody` / `uiFold`.

`TreeView` это не использует. У него свой `UiTreeView`. В кадре два «дерева». Секция должна быть заголовком и клипом высоты (`uiReveal` уже есть в `Motion.cpp`). Строка дерева — слот виртуального списка.

`tickFoldMarks` и `onTree` правят `UiPaint` строки.

### `TreeView.hpp`, `TreeView.cpp`

Сборка на `Virtual` правильная: пул слотов, bind, глубина, открытие.

Чужое: каждая строка получает иконку `UiIcon::Folder` (`addTreeSlot`). Общее дерево рисует папку. Иконку отдаёт `onBindNode`. Шеврон — да, это часть строки.

Краска иконки пишется сырым `paint.r/g/b` из `look.text` и `look.accent`, токен `Custom` не ставится, тема эту иконку не перекрасит через `uiRestyle` так же, как кнопки.

### `Virtual.hpp`, `Virtual.cpp`

Пул на `kUiPoolCap` (32) — общий рециклер. Это тот кирпич, на который должны сесть список, сетка и дерево.

Заголовок включает `Scroll.hpp` и `uiVirtualAttach` пишет поля `UiScroll` (`contentHeight`, `onScroll`, `follow`). Виртуализатор зависит от полосы прокрутки. Полоса должна звать пул, не наоборот. Иначе список без скролла не собрать, а скролл знает про пул только потому, что пул в него влез.

В том же заголовке и простой список `UiVirtual` (fill, click), и геометрия слота, и попадание в строку. Список — виджет над пулом.

### `VirtualGrid.hpp`, `VirtualGrid.cpp` (475)

Сетка на пуле — верно. Рядом второй продукт: свой редактор ячейки.

`openEditor`, `readEditor`, `editor`, `editAt`, двойной щелчок, zoom, context, list-режим. Сетка должна сказать «начали правку индекса» колбэком. Поле ставит сборка и кладёт его в слот пула. Сейчас сетка хранит id чужого поля и сама делает `uiPlace` / `uiShow`.

### `Chrome.hpp`, `Chrome.cpp` и `Docking.hpp`, `Docking.cpp` (278)

Хром умеет только родить заголовок окна (`uiWindowChrome`) и повесить bin.

Поведение заголовка лежит в доке:

- `ChromePointer uiChromePointer` объявлен в `Docking.hpp`;
- перетаскивание за `UiTitleBar`;
- ресайз за `UiResizable`;
- `uiDockTo` переписывает `UiFlex` хозяина и панели (260×100 или 100×160 пикселей зашиты);
- оверлей зон дока рисует примитивы;
- один `UiDock` на мир.

Док — раскладка панелей. Заголовок и край окна — хром. Жест края не должен знать, как стыкуется панель, и не должен писать flex соседа руками: для ширины уже есть `uiSetWidth` / сплиттер.

`Docking.cpp` включает `Chrome.hpp` и `PrimitiveBatch.hpp`.

### `PropGrid.hpp`, `PropGrid.cpp` (1030)

Это уже продукт «инспектор», не виджет. Он включает Button, Menu, Field, Fold, Scroll, Slider, Splitter и сам:

- строит колонку подписей и хват;
- чек, число, меню, vec2, vec3, замок, сброс, образец цвета, секцию, фильтр, поиск;
- хранит `button[12]` и `section[12]`;
- пишет `paint.r = s.look.text[0]` и `paint.r = r` у образца;
- лезет в `UiSplitter`, `UiField`, `UiFlex`, `UiText`, `UiTree`, `UiScroll`.

Сборка инспектора должна выглядеть как ряд: подпись, затем `uiNumber` / `uiChoice` / `uiCheck`. Ширина подписи — один раз на колонке. Фильтр секций — список над этими рядами, не массив из 12 id внутри компонента.

Образец цвета с сырым RGB допустим только как данные «показать этот цвет». Токен здесь не при чём, но краска должна идти через одну функцию образца, а не через ручной `UiPaint` в инспекторе.

### `Breadcrumbs.hpp`, `Breadcrumbs.cpp`

Виджет пути на диске: `root[512]`, склейка `root + tail`, `uiFindName` в `uiBindCrumbs`, кнопки сегментов, разбор `/`.

Кирпич — ряд сегментов: текст, щелчок по индексу. Путь, корень и запрет выйти из проекта считает файловый слой и отдаёт готовые куски. Склейка корня с нажатым сегментом как раз удваивает папку, если её оставить здесь.

### `AssetSlot.hpp`, `AssetSlot.cpp`

Слот файла: подпись, кнопка очистки, browse, `uiDragAddHost`, `uiAssetOfferPath` по предкам под курсором.

Общий кирпич — ячейка с текстом и колбэком. Путь, дроп файла и кнопка «x» задаёт файловый браузер. Слот не должен знать `DragDrop`.

### `DragDrop.hpp`, `DragDrop.cpp`

Жест переноса и метка вставки. Одно дело, но:

- призрак и маркер — свои узлы, которые модуль показывает и прячет сам;
- ветка `has<UiVirtualPool>()` значит, что перенос знает устройство списка;
- один `UiDragDrop` на мир, второй жест затирает первый.

Шина источника уже есть на `UiState::dropBus` (`uiDragBegin` в `Node.cpp`). Получается две шины: `dropBus` и компонент `UiDragDrop`.

### `Image.hpp`, `Image.cpp`

Иконка-слот, смена слота, миникарта, пан, зум колесом. Плюс сырой белый `ink.r/g/b = 1` при альфе 0.

Показ картинки — поставить `UiImage`. Пан и зум — жест просмотрщика, его собирает тот, кому нужна миникарта. Кнопка не должна тянуть жест пана через этот заголовок.

### `Thumb.hpp`, `Thumb.cpp`

`uiThumb` на чужом узле то снимает `UiImage`, то пишет альфу, обводку, тень и сырой `look.text` в `UiPaint`. Это дырка в кирпич картинки. Достаточно `uiSetIcon` / поставить слот. Отдельный модуль, который правит краску соседа, не нужен.

### `Curve.hpp`, `Curve.cpp` и `Gradient.hpp`, `Gradient.cpp`

Короткие и по делу: точки кривой, остановки градиента, жест, decor.

Оба сами пишут примитивы и оба заводят свой `clamp01`. Рисунок — запись рампы (`emitRamp` уже есть, у градиента режим `UiRamp`). Жест двигает число 0..1. Пока decor — единственный способ нарисовать ломаную, это терпимо. Дублировать математику кадра в виджете не надо.

`kit/` их не оборачивает. Они уже почти кирпичи.

## Сборки, которые стали программами

### `kit/Color.cpp` (1000) и `widget/ColorPicker.hpp`

Заголовка в `kit/` нет. Состояние — синглтон `uiColor(s)`.

Один файл делает:

- HSV и RGB (это `core/color/Color.hpp`);
- hex и целые поля;
- синхронизацию слайдеров, образца, книги `ColorBook`;
- шапку окна, меню, кнопки MENU / PICK / закрытие;
- позиционирование попапа;
- пробу пикселя по уже нарисованным примитивам (`samplePixel`);
- `colorCustomDraw` колёса и рамп;
- bin-роль.

Книга цвета (`uiSetColorBook`) — правильная дверца наружу. Всё остальное должно быть набором: колесо как рампа, три `uiSlider`, одно поле, одна кнопка. Второй пикер сейчас не создать, все id лежат в одном компоненте мира.

Сырой `paint->r = colorR` на образце — данные цвета, не тема. Их ставит кирпич образца, не страница на тысячу строк.

### `kit/Calendar.cpp` (310) и `widget/Calendar.hpp`

Тоже синглтон, `calDay[42]`, плюс поле-цель `calTarget`.

Файл считает дни месяца, пишет текст и краску каждого дня, открывает и закрывает панель, пишет дату в `UiField`.

Кирпич — сетка 7×6 кнопок и подпись месяца. Какой день серый, а какой выбран, говорит колбэк. Куда записать дату, решает тот, кто открыл календарь. `widget/Calendar.hpp` хранит id всех дней, а рисует `kit/Calendar.cpp`. Пара «заголовок в widget, программа в kit» прячет зависимость: календарь включает Button, Field, Label, Panel.

### `widget/Widgets.cpp`

Реестр. Ему положено знать имена `uiButtonBin`, `uiFieldDecor`, `uiTreeInput`. Ему не положено жить под узлом.

Сейчас он забывает часть виджетов, и те зовутся сбоку: Fold, PropGrid, AssetSlot, Tabs, Tip, Thumb, Popover. Реестр неполный, скрытые связи идут через прямые включения.

## В каком порядке собирать пирамиду

Не разносить файлы пакетом. Сначала разрезать мешок, иначе новые файлы снова включат `State.hpp` и увидят всё.

1. Вынуть из `UiState` публичные поля продуктов (меню, поле, док, цвет, календарь, команды). Оставить мир, узлы, боксы, фокус, тему. Остальное — компонент того виджета, который им владеет.
2. Убрать `#include "ui/widget/Widgets.hpp"` из `Node.cpp`. Реестр вызывает хост после создания состояния.
3. Свести рисунок к записям: прямоугольник, глиф, иконка, рампа, фото. Decor виджета только заполняет число в компоненте. Пакет этот компонент читает и не знает имя виджета.
4. Вынуть `UiRange` из числа. Слайдер, спин и поле берут его, друг друга не включают.
5. Разнять кнопку и чек, меню и choice, секцию и строку дерева, хром и док, поле и поиск.
6. Цвет, календарь, инспектор, крошки, слот файла оставить сборками: они только вызывают кирпичи и передают колбэки. Синглтон на `world` убрать, id хранить на своём узле.
7. `Domain.hpp` и маску сцены унести к хосту. `BinNode` оставить flex и краску, поля ролей забирать хуком роли.

После этого новый виджет — это компонент, фабрика и хук ввода. Он не включает соседа и не пишет его краску.

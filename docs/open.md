## Дальше (план, не трогать до своего черёда)

Порядок — что открывает следующую работу, не по сложности:

1. **GPU BC7/BC6H** — CPU ISPC пока остаётся. Начинать с одного режима BC7 (mode 6 — одна партиция, без ротации, проще остальных) не с перебора всех 8 режимов. Golden-image инфраструктура (`tests/Core.cpp`) уже есть — писать decode-верификацию сразу вместе с энкодером, не после.
2. **-DBH_TSAN=ON прогон** многооконной нагрузки (job system, Фаза 1.5) — мьютексы расставлены по ручному аудиту, не подтверждены инструментально. Дешёвая проверка, надо сделать раньше, чем наращивать больше параллельного кода поверх.
3. **Параллелизация внутри одного окна** (разбить `uiLayout` одного дерева виджетов по потокам) — не начато, Фаза 1.5 распараллелила только между окнами. Нужно только если один экран с одним огромным деревом становится бутылочным горлом (пока не измерено на реальном контенте).
4. **MSDF/MTSDF атлас** — сейчас SDF FreeType на весь атлас при смене размера, нет ленивого глифа. Генератора MSDF в системе нет (надо ставить).
5. ~~CSS-подобные функции (transform/filter в `UiPrimitive`, План Фаза 4)~~ — сделано: `UiPaint.angle/scaleX/scaleY/bright/contrast`, упаковка в `pad0`/`pad1` через `uiPackTransform`/`uiUnpackTransform` (`Model.hpp`), `kUiFlagTransform` в `ui.slang` (один draw, обе ветки `uiVs`/`uiMs`), `Panel::transform`/`Panel::filter`. Blur для фото (мип вместо второго прохода) не сделан — отдельный пункт ниже.
5a. **Blur для `kUiFlagPhoto`** — сэмплировать существующий более грубый мип текстуры (`core/image` уже строит цепочку) вместо второго прохода. Не начато.
6. **CMAKE_CXX_STANDARD → 26** — ещё не сделано и не проверено на сборку (пункт `cxx26` в плане висит отдельно).
7. **Полная изоляция падения модуля** (отдельный процесс/WASM) — большая отдельная задача по собственному признанию пользователя, не точечная правка. Не начинать без отдельного обсуждения архитектуры (процесс vs WASM vs поток с сигналом) — слишком крупное решение для точечного патча.

## Поставить

Уже стоят и подключены: `vulkan-headers`, `vulkan-validation-layers`, `vulkan-tools`, `sdl3`, `freetype2`, `python`, `shader-slang`, `ispc`, `clang`, `gcc`, `doctest`, `cpptrace`, `backward-cpp`, `renderdoc`. Повторно ставить не нужно.

Tracy в репозиториях CachyOS нет. `cmake -DBH_TRACY=ON` забирает её через FetchContent с `https://github.com/wolfpld/tracy`. Без флага зоны пустые.

Санитайзеры: `-DBH_ASAN=ON` или `-DBH_TSAN=ON`. Обычный debug их не включает.

## Ещё нет

- MSDF / MTSDF атлас 2048 и ленивый глиф. Сейчас SDF FreeType на весь атлас при смене размера. Генератора MSDF в системе нет.
- Offscreen-рендер UI сделан (`tests/Core.cpp`, golden-image тесты) — устройству нужен только `Device`, не поверхность; раньше здесь была ошибочная запись, что это невозможно без surface. Сравнение с эталоном в виде PNG на диске не сделано (эталон пока только аналитический — точный цвет заливки и mesh-vs-vertex), но сама offscreen-труба (рендер в свою картинку без свопчейна) теперь есть.
- GPU-компьют энкодер BC7/BC6H (план рендера, Фаза 2). BC1 сделан (`core/image/compress.slang`, простой per-channel min/max, без перебора партиций — один поток на блок). BC7/BC6H — другой класс сложности: поиск по ~64 формам партиций и режимам эндпоинтов, корректная реализация с нуля в разумный бюджет не влезла. Теперь есть golden-image инфраструктура (offscreen-рендер + эталонный декодер в тесте, `tests/Core.cpp`) — когда кто-то возьмётся за BC7/BC6H GPU-путь, проверять тем же способом: декодировать и сравнить со источником, не байт-в-байт с CPU ISPC.
- Полная изоляция падения модуля (план, Северная звезда: «один модуль упал — движок не упал»). Сейчас есть только `BH_ASSERT`/`bhFail` — громкий останов со стеком вместо тихой порчи в debug, применён в `ImageFile.cpp`. Это ловит баг разработчика до релиза, но не останавливает падение в релизе и не изолирует один поток/окно от остальных (один процесс, один `VkDevice` на все окна). Настоящая изоляция — отдельный процесс или WASM-песочница для кастомных модулей, как в плане; не начато, это отдельная крупная задача, не точечная правка.
- Параллельная запись командных буферов по окнам (план, Фаза 1.5, «job system») — сделано: `core/platform/Jobs.hpp` (fork-join пул) + `core/host/Host.cpp` (3 фазы, параллельная фаза 2 на `jobsRunAndWait`) + `Device::queueMutex` (общая очередь и upload-пул). Проверено на реальном GPU с двумя окнами одновременно, 0 ошибок валидации. НЕ сделано и не начато: прогон с `-DBH_TSAN=ON` (санитайзер потоков) под реальной многооконной нагрузкой — мьютексы расставлены по ручному аудиту общих ресурсов (очередь, upload-пул), не подтверждены инструментально. Параллелизация внутри одного окна (разбить `uiLayout` одного дерева на потоки) не сделана — распараллелено только между окнами.

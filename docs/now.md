# Burnhope — сейчас

Этот файл читается первым. Сначала закон, ниже — что уже запущено.
После правки кадра (`core/rhi`, `core/ui`, `core/platform`, `core/image`, `core/files`) его обновляют в том же заходе. Демо и движок ядро не правят.

## Закон

Новое делает только то, чего ещё нет. Всё остальное — вызов уже готового слоя снизу. Слой не копирует нижний и не знает задачи верхнего.

Слои снизу вверх:

1. Окно — `core/platform`. Ввод за кадр, без виджетов.
2. GPU — `core/rhi`. Картинка, буфер, шейдер, один draw. Не знает ни виджетов, ни файлов, ни сцен.
3. Картинка — `core/image`. Декод и сжатие, потом отдаёт текстуру в `rhi`.
4. Виджет — `core/ui/widget`, один файл на виджет. Рисует себя через общий draw и пишет свои данные.
5. Правка текста — `core/ui/widget/TextEdit.cpp`. Байты, каретка, UTF-8. Не рисует.
6. Данные — `core/ui/Json.cpp`. Документ, не картинка экрана.
7. Разметка — `core/ui/Layout.cpp`. Статичный экран описан JSON и на сборке печётся в плоский блоб. Кадр читает блоб и не разбирает этот текст. Загрузчик вызывает тот же `spawn`, что и ручной C++. Имя узла — сущность Flecs. Хром, календарь, цвет, меню и картинка раскрываются по роли.
8. Сборка руками — `core/ui/Panel.hpp` и `spawn`. Это первый интерфейс создания нод. Его не удаляют и не прячут за JSON. Процедурный виджет, таймлайн, граф и быстрый набросок пишутся здесь. В уже загруженный узел входят через `Panel::find` / `uiFindName` и дальше зовут `child`, `button`, `spawn`.
9. Сборки ядра — `core/ui/kit`. Цвет и календарь: дерево виджетов и своя политика. Демо не собирает 42 клетки дня и не рисует кнопки окна.
10. Проводник — `core/files`. Те же кнопки, поле, слайдер, разделитель. В кадр входит через `filesAttach`.
11. Кадр — `core/host`. Окно, swapchain и холст уже собраны. Снаружи задают размер, заголовок и функцию, которая наполняет холст. Запись сцены — список вызовов. Тело каждого прохода лежит в своём файле: `PassCull`, `PassSun`, `PassPoints`, `PassVis`, `PassShade`, `PassRadiance`, `PassTonemap`, `PassClusters`. Небо пишет `Sky.cpp` внутри shade: три LUT, панорама (`atmViewScale` 6), верхний слой проб, после ламп луч `reflect.slang`, после тумана облака. Прямое солнце — `sunIntensity / 5000`. Режим GI показывает SH и небо; пустой RC кадр не затирает. Контакт по умолчанию 20 см. Виды: 8 только прямой, 9 альбедо, 10 NdotL·тень·солнце. Лампы, туман, облака и луч в этих видах не пишут. Выключенный своим флагом модуль выходит сразу. Сцена пишет свой буфер и возвращается, свопчейн она не переводит в present. Хост открывает `uiCmd` и сабмитит его следом: тонмап уже закрыл проход с `LOAD_CLEAR`, холст ждёт этот сабмит, грузит картинку и рисует поверх. Сцена холст не записывает. Если `uiCmd` не открылся, холст дописывается в буфер сцены тем же порядком.

### Контракт разметки

C++ API сборки — фундамент, не временный путь. Загрузчик блоба только вызывает его.

1. Два входа, один спавн. `Panel`, `spawn`, `child`, `button`, `slider`, `label`, `field`, `check`, `spin` остаются публичными. Ими пишут процедурные списки, таймлайны, графы и быстрые пробы. Статичный экран — `assets/ui/*.json`, офлайн `tools/uibake.py`, кадр читает `.uib`. `uiImportBin` — клиент `spawn`, не замена.
2. Поведение узла из блоба — только по имени: `uiFindName`, `canvasFind`, `uiBindName`, `canvasBindName`, `Panel::find`. Порядок создания и сырой номер сущности не контракт. Смена паддинга, цвета и порядка в JSON не рвёт C++.
3. Хром, календарь, цвет, меню и картинка живут в `core` и раскрываются ролью (`calendar`, `color`, `chrome`). Демо их сетку не собирает. Путь шрифта по умолчанию пишет только `canvasUseFont`. `canvasSetFont` — для пути, который выбрали в рантайме.

```
assets/ui/*.json  →  tools/uibake.py  →  .uib  →  uiImportBin  ┐
                                                                ├→  spawn / Yoga / Flecs
Panel, child, button, label, field, slider, spin, spawn  ─────┘
```

Полный список функций — `docs/api.md`.

Уже есть и второй раз не писать: `uiDrop` снимает поддерево с Yoga (`YGNodeRemoveChild` + `YGNodeFreeRecursive`) и уничтожает сущности Flecs, слоты не уплотняются, кадр пропускает мёртвые. Клип по предкам с `overflow` hidden/scroll в том же draw (прямоугольник в примитиве, не второй проход Vulkan), флаги `layoutDirty` / `visualDirty`, `uiMarkLayout` считает поддерево, Tab и Shift+Tab через `uiFocusStep` по `UiTab.index`, док и сплиттер, двойной клик по слову. Пул строк — `uiVirtual` (12 слотов, данные снаружи). Число с протяжкой — `uiSpin` / `Panel::spin`, на время тяги включается относительная мышь и курсор возвращается в точку захвата. Строка дерева — `uiTreeRow`. Кривая — `uiCurve` / `Panel::curve`, лента считается в вершинном шейдере того же draw (`kUiFlagRibbon`). Частичный `uiLayout` сохраняет уже посчитанную высоту узла, чтобы прокрутка не схлопывала окно. Кнопка, крестик и галочка без явной ширины берут ширину подписи. Полоса градиента — `uiGradient` / `Panel::gradient`. Отмена поля — Ctrl+Z / Ctrl+Y, восемь снимков. Шина переноса — `uiDragBegin` / `uiDragEnd`, список начинает перенос после 4 px, приёмник с `UiDropTarget.kind` фильтрует payload. Escape закрывает меню и сбрасывает перенос. Очередь transfer отдельно от graphics; заливка картинки копирует на ней и захватывает на graphics. Ресайз свопчейна передаёт `oldSwapchain`. Yoga считает в точках (`пиксели / dpi`), вьюпорт остаётся физическим. Смена масштаба пересобирает SDF. IME: `TEXT_EDITING` и `SDL_SetTextInputArea`. Свёрнутое или без фокуса окно спит 32 мс; `FrameDesc.hz` > 0 включает `platformPace`. Незакрытое — `docs/open.md`.

Нет отдельного виджета вкладок: соседей прячет `uiShowOnly`. `uiFieldMulti` включает многострочное поле: Enter вставляет перевод строки, каретка и выделение идут по строкам, ширина поля переносит строку. Примитив квада — 80 байт: четыре радиуса (`radius`, `radiusTr`, `radiusBr`, `radiusBl`; отрицательный угол берёт общий `radius`). Панель с `ramp` рисует линейный градиент тем же шейдером. Тень — спад SDF (`kUiFlagShadow`). Обводка — `borderW` и `fwidth`. Полный список функций — `docs/api.md`. Незакрытое — `docs/open.md`.

### Сверка задания

Повтор в задании не значит, что куска нет. Чего ещё нет — только `docs/open.md`.

Уже есть, второй раз не писать:

- Реестр окон в `core/host`: до 8 слотов, у каждого `SDL_Window`, свой swapchain и свой холст Flecs. Командный пул graphics один на устройство. Если transfer — другое семейство, у него свой пул.
- Ресайз: `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED` ставит флаг, новый swapchain создаётся в начале кадра с `oldSwapchain`. Размер 0×0 не вызывает acquire и present. Без фокуса кадр спит 32 мс. `platformPace` режет частоту, когда `FrameDesc.hz` больше нуля.
- Безрамочный хит-тест в точках окна: `SDL_SetWindowHitTest`, заголовок — `SDL_HITTEST_DRAGGABLE`, край — `SDL_HITTEST_RESIZE_*`.
- Окно: размер, min/max, позиция, bordered, resizable, always-on-top, прозрачность, opacity, фокус. `windowFullscreenKind`: 0 окно, 1 borderless, 2 exclusive. `windowRemember` / `windowRecall` пишут геометрию в `$HOME/.cache`. `windowCenter` и `windowToDisplay` двигают окно. `windowClickThrough` ставит прозрачную форму.
- Present: FIFO, FIFO relaxed, mailbox, immediate, нет режима — FIFO. Два кадра в полёте. Клик пишет `clickTick`, `vkWaitForPresentKHR` кладёт миллисекунды в `photonMs`.
- `swapchainSubmitPresent` принимает `pace` (по умолчанию `true`): если `true`, режим не `Immediate` и есть `presentWait`, кадр блокирует вызывающий поток до реального появления на экране (`vkWaitForPresentKHR(..., UINT64_MAX)`). `Immediate` это ожидание пропускает, поэтому окно сцены не сидит на 60 Гц. `core/host/Host.cpp` передаёт `pace = (slot == host.primary)`.
- Ввод кадра: x, y, dx, dy, колесо X и Y, ЛКМ/ПКМ/СКМ/X1/X2, `keyEdge` / `keyDown` / `keyUp`, `windowHoldMs`, Ctrl/Shift/Alt/Super, CapsLock, NumLock, UTF-8, композиция, зона IME. Сглаживание `dx`/`dy` включается `windowMouseSmooth`.
- Хит-тест с конца дерева. `Hidden` пропускает луч. Выключенный узел глотает клик. Ножницы только у скролла и overflow hidden/scroll. Захват мыши у слайдера, скролла и сплиттера; сплиттер держит `windowMouseRect`. Перенос после 4 px, `UiDropTarget` фильтрует kind. Двойной и тройной клик: 400 мс и радиус 4 px.
- Фокус один на окно. Tab идёт по `UiTab.index`, иначе по id, и заворачивается. Escape снимает фокус, закрывает меню, бросает перенос. `uiSyncInput` зеркалит hover, focus, capture и press на сущности.
- Поле: индекс по X, anchor/caret, восемь снимков. `UiField.multi` вставляет `\n`.
- Курсоры 0–11 и стек `uiCursorPush` / `uiCursorPop`. `windowCursorRgba` делает цветной курсор. Относительная мышь возвращает точку захвата.
- Действия: до четырёх аккордов, press/release/hold, digital/axis, стек контекстов, `actionListen`, JSON в `$HOME/.cache/burnhope-actions.txt` при старте и выходе кадра.
- UI: один draw, квад, четыре радиуса, `fwidth`, клип предка в примитиве, тень спадом SDF. Прозрачное окно смешивает premultiplied. `cmdSetGraphicsDynamic` принимает режим 0–4 (straight, premultiplied, additive, multiply, screen). Панель с `ramp` красится градиентом.
- Отрисовка UI теперь двупутевая по возможностям GPU, не по выбору на старте: если `DeviceCaps.meshShader` — `uiMs` (mesh shader, `vkCmdDrawMeshTasksEXT`, 4 вершины + 2 индексированных треугольника на примитив) через `cmdBindMeshFrag`; иначе — старый `uiVs` (vertex-pull, `vkCmdDraw(drawCount*6,...)`) через `cmdBindVertFrag`. Общая математика примитива — одна функция `uiPrimVertex` в `ui.slang`, оба пути зовут её, фрагментный шейдер `uiFs` не меняется. Если создание `uiMs` ShaderEXT не удалось — `Canvas.ms.handle` остаётся null и кадр молча падает обратно на vertex-pull, никогда не теряя кадр целиком. Это тот же единственный SSBO и тот же один draw в кадр — не второй рендер, просто два способа подать его GPU.
- Картинка: если семейства разные, копия идёт очередью transfer, затем graphics захватывает в shader read.
- Валидация в debug включает synchronization validation. Барьер кадра перед отрисовкой разрешает и чтение, и запись вложения, потому что `loadOp` читает цвет. Устройство и проход UI получают имя `debug_utils`. F12 зовёт `rhiCaptureToggle` (`librenderdoc.so`; кадр пишется, если процесс запущен под RenderDoc).
- `DeviceCaps.maintenance6`/`hostImageCopy` — ядро Vulkan 1.4 (`VkPhysicalDeviceVulkan14Features`), обнаружение в `fillCaps` теперь напрямую гейтит то же поле в структуре, которую `deviceCreate` реально передаёт в `vkCreateDevice`: раньше `maintenance6` определялся как `true`, но никогда не включался у драйвера — тихий разрыв между «caps говорит да» и «GPU получил фичу». Правило на будущее: каждое новое булево поле `DeviceCaps` обязано использовать ту же переменную для обнаружения и для фактического запроса фичи, не две копии.
- `DeviceCaps` расширен под план 2026: `swapchainMaintenance1`, `nestedCommandBuffer`, `depthClampControl`, `fragmentShaderBarycentric` обнаруживаются и включаются на устройстве (потребителей пока нет — задел под Фазы 1.5/5+, список в `docs/api.md`). `cooperativeMatrix` только обнаруживается и пишется в лог, фича не включается — нет потребителя ни в одной фазе (Северная звезда — будущий ReSTIR/нейро-апскейл). `VK_EXT_swapchain_maintenance1` тянет за собой два инстанс-расширения (`VK_KHR_get_surface_capabilities2`, `VK_EXT_surface_maintenance1`) — `deviceCreate` сам проверяет их наличие до создания инстанса и обнуляет `caps.swapchainMaintenance1`, если прероквизит не найден, чтобы поле не врало.
- DOD/Flecs аудит горячего пути кадра (Фаза 3 плана рендера): прочитаны `uiLayout`, `uiEmit`, `hitTest`, `uiApplyInput` — ни один не делает `std::vector`/`malloc` внутри кадра, только `ids[kUiCap]` на стеке в `uiEmit` и SoA-массивы `UiState`. Сортировка в `uiEmit` — вставкой по уже почти отсортированному порядку спавна (O(n) на практике), не `std::sort`. Замер подтвердил догадку числом: `uiEmit` на том же дереве примерно в 6 раз дешевле `uiLayout` (1.3 мс против 8.5 мс на 510 узлах) — следующая оптимизация производительности имеет смысл только в Yoga/`uiLayout`, не в сборке примитивов. Ничего не переписано: аудит подтвердил, что структура уже DOD, не нашёл нарушения.
- `core/image/ImageFile.cpp`: `submitImage` сначала пробует прямую CPU→GPU загрузку через Vulkan 1.4 host image copy (`vkCopyMemoryToImage`/`vkTransitionImageLayout`, без staging-буфера и командного буфера), и только если это не удалось или формат/GPU не поддерживает — старый путь со staging-буфером. Это не второй декодер и не второй путь сжатия: байты те же, меняется только как они попадают из CPU-памяти в GPU-текстуру. Проверено тестом на реальном GPU с multi-mip BC7. Сжатие BC держит одну кучу и один шейдер на все мипы. На GPU уходит только мип 0 от 2048; меньшие мипы считает ISPC в `jobsRunAndWait`, пока этот проход ещё на очереди. Готовый DDS лежит в `cache/textures/` и следующий запуск читает его без компрессора. Имя текстуры в блобе короче файла на диске: загрузка дописывает расширение и ищет префикс в той же папке. Пустой слот — несжатая 1×1 (белый, плоская нормаль или ORM), в кучу не пишется `VK_NULL_HANDLE`. Картинки SSR и bloom создаются после `ssrPassCreate` и `tonemapPassCreate`: эти функции в начале уничтожают свои `GpuImage`, и созданный раньше half/bloom до записи дескрипторов уже был нулевым. Слоты текстур — 768 штук с 16: в 640 не влезали шторы и хвост Sponza, материал получал белый слот 0. Шрифт UI — 800, фото — 801. Аргументы тени солнца разделены по двум кадрам в полёте, иначе очистка одного кадра обнуляла отрисовку другого. Сэмпл текстуры сцены видит всю цепочку мипов и фильтруется анизотропией 16× (`SampleGrad`). CMAA2 сглаживает ребро кадра перед тонмапом. UV и нормаль интерполируются с перспективой, параллакс сдвигает UV не больше чем на 0.006. Альфа альбедо ниже 0.5 выкидывает пиксель и в кадре, и в тени. Лампа рядом с камерой попадает в кластер, даже если её центр за спиной. Три ближайшие свечи получают карты теней. Буфер кадра и лампы лежат в двух копиях, у каждого кадра своя куча дескрипторов. Проходы одной очереди сцеплены timeline-семафором, процессор чужой fence не ждёт. SSRC берёт ближайший зонд и альбедо попадания, не HDR. Дальний каскад солнца до 1800 м. Зерно по умолчанию выключено. У входа Sponza стоит зеркальный квад.
- Треки анимации — `core/anim/Animation.hpp`. `UiAnim` по-прежнему короткий цветовой переход. Ключи сэмплирует `animSampleTrack`, время пачки двигает `animTickPlayers`.
- Время кадра — `core/time/Time.hpp`. `rawDelta` для UI и треков, `timeAdvance` копит фиксированный шаг и отдаёт `alpha` для сглаживания. Скачок режется `maxAccumulation`.
- Стили виджетов — `core/ui/Style.hpp`. Класс — число `uiClassHash`. Каскад пишет в готовый `UiStyle`. Отступы и размер уходят в тот же узел Yoga через `uiStyleApplyYoga`.
- Ввод устройств — `core/input/Input.hpp`. Кольцо на 128 `InputEvent`. `InputFrame` остаётся снимком SDL. Первое движение мыши ставит точку и не даёт дельту от нуля. `consumed` помечает клавишу в `keyConsumed`.
- Цвет, документ и строка — `core/color`, `core/doc`, `core/text`. Пикер берёт HSV из ядра. Поле и его восемь снимков undo не заменены. `textLayoutLine` пишет клип, `glyphMs` собирает квад в одной mesh-группе.
- Файл в память — `core/io`. Материал — `MaterialGpuData` 64 байта за заголовком `BHOP`. Инспектор пишет в `dataPtr` из `InputState`. Статистика кадра форматируется в буфер для `textLayoutLine`.
- Мешлет, кластер света и Hi-Z — `core/gfx`. Конус мешлета зовёт ту же формулу, что камера. Лампа попадает в ячейки сетки `16×9×24`. Блоб мешлетов читается из `mmap`.
- Резолв visbuffer — 20 бит инстанса и 12 бит примитива, материал по `materialId`. Солнце — ортокамера 2048 и PCF 3×3 в `resolve.slang`. Стартовая сцена — пол, три куба, три лампы. Draw по-прежнему один `meshDrawRecord`.
- Стриминг — `core/stream`. Кольцо чанков, очередь на 128, резидентность по хешу. Кадр кольцо не аллоцирует.
- Окно сцены открывается сразу: `./build-core/BurnhopeEngine`. ПКМ и WASD двигают `FlyCam`. Занятый GPU не пропускает шаг камеры. Кадр включения захвата мыши не крутит взгляд. Взгляд почти вертикально вниз берёт запасной up `(0,0,±1)`, матрица вида не взрывается. Пол лежит в `y = 0`, кубы стоят выше плоскости на 2 см. Мешлет пишется целиком, до 64 вершин и 124 треугольников. `FrameView` (384) и `FrameSun` (1920) и восемь блоков ползунков по 64 байта совпадают в `frame.slang` и в C++. Солнце пишет поверхность в две картинки, лампы их читают и `shade_hit` не включают. Короткий закон — `docs/law.md`. Перед потерей устройства сцена отпускает свои буферы. Старое окно интерфейса — `./build-core/BurnhopeEngine --ui`.
- Bistro: `sceneImportFbxList` читает `BistroExterior.fbx`, `BistroInterior.fbx` и `BistroInterior_Wine.fbx` через Assimp и пишет `cache/bistro.bhop` версии 8. При сборке меша треугольники не режутся по длине ребра. Лампа берёт мировую матрицу своего узла. и пересчитывает нормали. К альбедо, если файл лежит рядом, добавляются `Normal` и `Specular`. Лампы карты пишутся в блоб. В блобе версии 9 рядом с LOD 0 лежит LOD 1, граница кластера не двигается, переход 12–16 px режется дополняющей матрицей Байера: у LOD 0 порог положительный, у LOD 1 тот же порог со знаком минус. Сетка ламп и списки каскадов солнца считает compute. Сектор без размеченных порталов не выкидывается. Луч окклюзии не используется. Альбедо сэмплится с повтором (`HeapSamp::Wrap`); тени остаются с зажимом по краю. Если у материала проекция BOX или у меша нет UV, координата берётся из XZ мира. Тень солнца выбирается по дистанции взгляда и смешивается на стыке 28–48 м и 140–220 м. Дальше 220 м остаётся третий каскад, он не гасится. Точечная лампа с радиусом меньше 8 м поднимается до 22 м и яркости 8, грань тени берётся по направлению от лампы к точке. Туман — десять шагов от камеры до поверхности, плотность и высота в панели. SSR на дистанции шагает долю глубины, порог попадания не отсекает дальнюю обратную глубину. GTAO больше не считает дальнюю обратную глубину пустой и тянет выборку на радиус в пикселях. SSCS, SSR и SSRC читают длину, толщину и число шагов из хвоста кадра, ползунки на панели. Хвост после тумана — пять отдельных uint, не массив: иначе шейдер сдвигает ручки. Длина SSCS — это ползунок в метрах, попадание — поверхность ближе к камере, чем точка луча, в пределах толщины. UV треугольника считается по точке мира, не по проекции на экран. GTAO — срез полусферы и обе стороны, как XeGTAO, спад гасит дальний образец. Тень берёт самую плотную карту, в которую точка попала. Экранные каскады излучения режут один луч по `t_n = base * 4^n` и склеивают интервалы с дальнего. Центр сферы снапится на несколько текселей. Атлас 2048×6144, полоса 2048², только глубина, reverse-Z, выборка точечная внутри полосы. Чистится одна полоса. Перерисовывается только каскад, чья матрица сменилась. SSR пишет в половинный буфер только добавку отражения. Toksvig добавляет квадрат дыры нормали, без деления на её длину. `post[12]` в шейдере — три `float4`. Цепочка: LOD 0 и 1 в каскаде 0, LOD 0–2 в каскаде 1, в дальнем — самый грубый не выше 2, а если его нет, то LOD 0. Контактная тень солнца — 15 см, толщина 1.5 см, не длиннее 16 пикселей. Мешлет меньше 1.5 px отсекается в compute, до списка Early. Сфера меньше 2 пикселей каскада отсекается. Снап на тексель не меняет матрицу — карта того кадра остаётся. PCF 5×5. Флаг окклюзии: 0 вне пирамиды (ранний проход), 1 нарисован, 2 скрыт Hi-Z (поздний проход), 3 ждёт подтверждения пирамидой этого кадра. До трёх точечных или прожекторных ламп карты получают теневой атлас 1536×768. Остальные точечные и прожекторы светят из сетки 16×9×24, направленный свет карты в эту сетку не пишется — его уже даёт солнце. Яркость лампы в шейдере режется до 1.2, блик GGX до 2, SSRC берёт из кадра не больше 0.85 и добавляет не больше 0.45. Барицентрики нормали и UV света считаются на экране по проекции трёх вершин. Альбедо и шероховатость не сравнивают мировую точку с локальной вершиной. Панель статистики держит галки SSR, SSRC, Hi-Z и конуса и переключатель вида: свет, номер треугольника, нормаль, только отражение, только каскад. Флаги лежат в хвосте `FrameGPU` (`debugMode` и четыре `disable*`). Смена пишет `debug`. Переход LOD хранит оба фактора в диапазоне 0…1. Подробный уровень выкидывает пиксель, когда Байер не меньше фактора. Упрощённый выкидывает, когда Байер меньше того же фактора. Границы 32, 16 и 8 px. Промах отражения берёт куб сцены: вдоль нормали плоскости, если поверхность гладкая, и от сферы сцены, если шероховатая. Пустой тайл 16×16 в свете сразу пишет небо. Перед уничтожением шейдеров и картинок кадр ждёт `vkDeviceWaitIdle`. Камера не перебирает мешлеты на CPU. Compute рисует сначала те, что были видны в прошлый раз, по их глубине строит пирамиду максимума и только потом проверяет остальные. Поздний шейдер кадра 0 читает только свою пирамиду, кадр 1 — свою. Ранний кулл, очистка счётчиков и меш камеры тоже собраны дважды: номер кадра — константа `CULL_FLIGHT`, не поле общего UBO. Пирамида минимума остаётся у отражений. Сфера на ближней плоскости в Hi-Z не идёт. Конус нормалей берётся с мешлета. Треугольник меньше 0.75 px по обеим осям выкидывается, только если все вершины дальше ближней плоскости. Ламп в буфере до 10240, свечи Sponza — узел на лампу. Блик глушится окклюзией по углу и шероховатости, GGX возвращает энергию повторных отскоков, нормаль на мипе расширяет шероховатость. Шейдер читает `gLights` / `gCells` / `gLightIds`. Шероховатость в альфу кадра, SSR добавляет отражение только когда глянец заметен. Куб и тени ламп снимаются один раз. Папки над ядром. Они подключают `core` снаружи и живут своей жизнью:

- Демо — `demo/`. Экран SCENE / LOOK / INPUT и оболочка. Она не открывает surface и не вызывает SDL: только `hostOpen` с размером окна и своей функцией сборки.
- Движок — `engine/`. Visbuffer, свет, сцена. В этот exe не входит.

`old/` — старый редактор, старые шейдеры и старые библиотеки. Его не читают, не импортируют и не правят. Живой код — только `core`, `demo`, `engine`.

Физическое разделение по папкам — закон сборки. Пока код лежал рядом, демо-логика уезжала в базовые виджеты.

`core` — чистые модули. Они не знают конкретного приложения, цветов темы экрана и кнопок закрытия окон. Ядро компилируется изолированно и не имеет права подключать ничего из `demo` и `engine`.

`demo` и `engine` работают на основе ядра. Они подключают его как библиотеку и только там решают, что кнопка делает при клике. Потом демо и движок живут своей жизнью.

На сборке это зацементировано: у целей ядра в include path только `core/`. Демо видит ядро. Ядро проект демо и движок импортировать не может: `CMakeLists.txt` обрывает конфигурацию, если в `core/` есть `#include` на `demo/`, `engine/` или `../`. Тогда панель нельзя прописать внутрь кнопки так, чтобы это собралось.

Компоненты ядра не знают контекста приложения. Они предоставляют только события (нажатие, изменение, фокус) и принимают действия снаружи. Никакой зашитой прикладной логики внутри виджетов.

Перед любым кодом: это уже есть? В каком слое? Добавляется только дырка.

### Как надо. Образец — инпут

Фон поля — та же заливка, что у панели (`emitRect` по роли). Поле её не рисует заново.

Буквы — отдельная сущность `Label`. У кнопки, крестика, галочки и поля её номер даёт `uiTextId` / `canvasTextId`. Строку по-прежнему задаёт `uiText` на хозяине: кадр копирует байты на подпись. Стиль живёт на подписи и кадр его не затирает. Горизонталь (включая justify), вертикаль, перенос, «...» в конце и в середине, подчёркивание, зачёркивание, надчёркивание, интервал строк, межбуквенный и межсловный зазор, отступ первой строки, регистр, таб, разрыв внутри слова, размер, толщина декора и тень букв делает `textRun`. Полный список того, что уже есть и чего нет, — `docs/widgets.md`. Его читают до новой фичи виджета.

Само поле добавляет только то, чего у панели и подписи нет: каретку, подсветку выделения, кнопку очистки, рамку фокуса и ошибку.

Кнопка, крестик, галочка, пункт меню и строка списка буквы не рисуют. У каждого ребёнок `Label`. Кнопка добавляет иконку и контрастный цвет. Галочка добавляет квадрат или круг. Меню и список — панель из этих кнопок.

Слайдер пишет число, рисует дорожку и ползунок. Рампа — номер в `UiPaint.ramp` и оттенок в цвете заливки. Какой это канал, пишет редактор цвета, не слайдер.

Ошибки этой сборки и почему их нельзя повторять — `docs/mistakes.md`. После каждой правки структуры сюда пишется решение: что уже было и что добавлено. Если форма была неверной, вывод дописывается в `docs/mistakes.md` до конца задачи.

Вставка, стирание символа UTF-8, слово, прокрутка каретки — `TextEdit.cpp`. Поле и меню вызывают эти функции.

Слайдер пишет число и зовёт `canvasListen`. Высоту превью пишет `Shell`, не слайдер. Кнопка файла зовёт `onClick`, оболочка зовёт `filesClick`.

### Как нельзя

- Рисовать свой текст, свою кнопку или свой фон внутри фичи, хотя подпись, кнопка и панель уже есть. Так поле раньше само вызывало `emitGlyphs`.
- Класть смысл в виджет. Слайдер не меняет размер превью. Поле не открывает файл. Кнопка не знает, что она «закрыть цвет» или «открыть дату». Она вызывает `UiAction`, которую задали `uiBind` там, где кнопку создали. Смена фокуса зовёт `canvasOnFocus`, не код экрана внутри виджета.
- Писать второй рендер, второй декодер или второй обход диска. Нет формата — его добавляют в `core/image`. Нет жеста — в виджет. Нет операции с файлом — в `core/files`.
- Подключать из `core` что-либо из `demo`, `engine` или `old`. Сборка это не примет.
- Открывать `old/` и переносить оттуда пайплайн, шейдер или окно. Новая дырка пишется в живом слое.
- Смешивать слои в одном файле. Правка строки не живёт в коде рисования. Проводник не живёт в `Input.cpp`.
- Начинать экран с нуля. Статичный экран — JSON. Процедурный кусок — `Panel` и `spawn` внутри уже существующего узла.
- Выкидывать `Panel` и `spawn`, потому что появился блоб. Загрузчик без них не из чего собирать ноды.
- Писать абсолютный путь шрифта в демо или в виджете. Путь по умолчанию знает только `canvasUseFont`.
- Вешать действие на узел из блоба по сырому номеру. Только имя: `uiBindName` / `canvasBindName`.

Запуск: `./build-core/BurnhopeEngine` из корня репозитория. Шейдеры UI зашиты абсолютным путём сборки.

## Что работает

Слои снизу вверх. Нижний работает сам, верхний только вызывает его.

- Окно и весь SDL — `core/platform`.
- Кадр окна — `core/host`. Демо его не собирает заново.
- GPU — `core/rhi`. Виджеты рисуются одним draw через него.
- Картинка (декод и сжатие) — `core/image`.
- Виджет — `core/ui/widget`, каждый в своём файле. Пишет данные и ничего не решает.
- Данные JSON — `core/ui/Json.cpp`. Это документ, не вёрстка экрана.
- Разметка экрана — `assets/ui/*.json` → `.uib` версии 2, узел 204 байта. Кадр читает блоб (`uiImportBin`). Имя узла стабильное. Поведение вешается `uiBindName` / `canvasBindName`. Роли `chrome`, `calendar`, `color`, `menu`, `image` ядро раскрывает само. Ручная сборка `Panel` / `spawn` остаётся и зовёт тот же спавн. Блок YOGA GROW в `Shell.cpp` — пример: скелет страницы из блоба, дети из C++ через `Panel::find`. Шрифт по умолчанию — `canvasUseFont`.
- Сборки ядра — `core/ui/kit` (цвет и календарь) и хром окна `core/ui/widget/Chrome.cpp`. Демо-экран — `demo/Sample.cpp`, он больше не спавнит клетки календаря и кнопки окна.
- Проводник — `core/files`. Встаёт в кадр через `filesAttach` и собран из тех же кнопок, поля, слайдера и разделителя.
- Программа — `demo/app`. Задаёт три окна: `main` (`shellBuild`), `tool` (`toolBuild`), `color` (`colorBuild`). Закрытие окна цвета обнуляет `ColorBook.present`.

Кадр — `hostTick`. `Main.cpp` крутит цикл, пока `hostQuit` ложен. `Engine` вызывает `hostInit`, `hostOpen` и `hostTick`.

### Ядро Vulkan 1.4 (`core/rhi`)

- Instance 1.4 через Volk, validation в debug, surface SDL3.
- Device: shader objects, dynamic rendering, sync2, timeline semaphore, BDA, descriptor heap. Caps пишутся в лог один раз (`shaderObject`, `presentWait`, `rayQuery`, `meshShader`, `dgc`).
- Нет mesh shader — кадр всё равно стартует. Если mesh shader есть, UI-draw явно биндит пустой mesh stage (так требует spec).
- `shaderDrawParameters` включён: вершинный шейдер читает `SV_VertexID`.
- Память — VMA. Буферы с host write делают `gpuBufferFlush`.
- Swapchain: режим из `FrameDesc` (`Present::Vsync`, `Mailbox`, `Immediate`, `Relaxed`). Нет запрошенного — FIFO. По умолчанию mailbox. 2 кадра, `vkQueueSubmit2`, present id + `vkWaitForPresentKHR`. Прозрачное окно берёт premultiplied alpha, если поверхность умеет.
- Shader objects: SPIR-V, точка входа у slangc называется `main`. Хранилище дескрипторов — `VK_EXT_descriptor_heap`, слоты без имён проходов. Число buffer/image/sampler задаёт вызывающий.
- Картинка: dynamic rendering, один color attachment, альфа-бленд для UI.
- Барьер кадра узкий: host write → vertex/fragment read на SSBO, затем layout swapchain в color attachment.
- Метки проходов — `core/rhi/GpuProfiler.hpp`. Пул timestamp на 192 слота (48 зон × 2 кадра в полёте). Зона пишет `vkCmdWriteTimestamp2` на вход и выход. Результат читается на следующем обороте того же слота, без ожидания очереди. CPU-область — `core/debug/CpuScope.hpp`. Кадр сцены вешает зоны на кулинг, Hi-Z, visbuffer, свет, GTAO, shade, SSR, блюм и тонмап. Выключенный тумблер не диспатчит этот проход.

### Платформа SDL3 (`core/platform`)

Окно Vulkan, resize в пикселях, DPI-масштаб мыши. Создание принимает заголовок, положение, размер, минимум и максимум, рамку, resize, скрытие, поверх всех, полный экран, фокус, модальность, плотность пикселей, прозрачность, вид (обычное, utility, tooltip, popup), непрозрачность, aspect и родителя. Дальше те же вещи меняются отдельными вызовами: перенос, размер, рамка, maximize, minimize, restore, show, hide, raise, родитель, grab клавиатуры и мыши, относительная мышь, вспышка, прогресс в панели задач, иконка из RGBA, форма, системное меню, безопасная зона и масштаб дисплея. Тема системы — `platformTheme` (0 неизвестно, 1 светлая, 2 тёмная). Хранитель экрана — `platformScreensaver`.

За кадр один `InputFrame`: позиция, края левой, правой, средней, X1 и X2, колесо X и Y, UTF-8, композиция, backspace, delete, стрелки, Home, End, Page Up/Down, Escape, Ctrl, Shift, Alt, Super, CapsLock, NumLock, `keyEdge` / `keyDown` / `keyUp`, Ctrl+A/C/X/V, tab, enter, F2, F5, F12, фокус окна и путь файла, брошенного в окно. Текстовый ввод SDL включает `windowText`, когда холст просит поле. Буфер обмена — `windowClipboardSet` / `windowClipboardGet`. Курсоры 0–11 и стек виджета. Кромка resize курсор виджета не перебивает.

Хит-тест безрамного окна: кромка `resizeBorderPx`, шапка `titleBarPx` до правых 120 px — перетаскивание. `windowChrome` пишет эти два числа с холста.

Диалог файла — `windowAskFile` (`FileAsk::Open`, `Save`, `Folder`). Фильтры копируются, вторая попытка пока диалог открыт возвращает false. Последняя папка пишется в `$HOME/.cache/burnhope-dialog.txt`. Готовый путь забирает `windowTakeFile`. Отмена пути не даёт.

`windowsPump` принимает список окон. Первое в списке получает `SDL_EVENT_QUIT`. Поверхность Vulkan для лишнего окна создаёт `deviceCreateSurface` в `core/rhi`. Единственный SDL вне платформы — этот вызов.

### Кадр (`core/host`)

До восьми окон. Имен палитры и панелей в кадре нет: окно — это `ViewDesc` со строковым id, который задаёт приложение. `hostOpen` с тем же id поднимает уже открытое окно. Первое окно главное: его закрытие ставит `hostQuit`. Остальные закрываются сразу, и если задан `onClose`, он вызывается после уничтожения. У каждого окна свои surface, swapchain, heap и холст. `FrameDesc` на дескрипторе — vsync, mailbox, immediate или relaxed; `hostSetFrame` меняет это у живого окна и пересобирает swapchain. Прозрачный `WindowConfig` включает прозрачный композит. Команды minimize, maximize, поверх всех и непрозрачность применяет сам кадр. Буфер обмена, курсор, текстовый ввод и F5 тоже. Просьба открыть файл открывает диалог и кладёт путь в поле холста; картинка идёт в слот 0, `.json` — в документ. Файл, брошенный в окно, идёт тем же путём. Остальные команды холста кадр не разбирает: их отдаёт `onOps`, и там приложение вызывает ещё один `hostOpen`.

### UI (`core/ui`)

568 сущностей Flecs 4 на демо-кадре. У кнопки, галочки, крестика и поля есть подпись-ребёнок, поэтому узлов больше, чем виджетов на экране. Колонки POD: `UiFlex`, `UiPaint`, `UiText`, `UiField`, `UiRange`, `UiCheck`, `UiScroll`, `UiImage`, `UiSlot`, `UiName`. Yoga считает боксы когда грязный размер или стиль. Попадание — по боксам, абсолютные слои рисуются поверх потока. В GPU уходит один SSBO и один `vkCmdDraw`.

Поле — панель плюс подпись. Фон рисует общая заливка, буквы — ребёнок `Label`. Само поле добавляет каретку, выделение и очистку. Байты UTF-8 правит `TextEdit.cpp`. Двойной клик выделяет только слово под курсором. Двойной клик выделяет только слово под курсором. Меню поля: CUT, COPY, PASTE, SELECT ALL, CLEAR, подпись на всю ширину пункта. Email без `name@host`, телефон короче 6 цифр и URL без точки получают красную обводку; пустое required тоже. READONLY не принимает ввод. Внутренние отступы и цвет текста — `padL`/`padR` и `text[]` у `UiField`. Страница INPUT скроллится. FILE просит диалог через `openFile`. Кадр открывает его сам. Фильтры: All, JSON, Images (`png;jpg;jpeg;gif;bmp;tga;hdr;psd`). Путь попадает в поле FILE. Картинка грузится в слот 0, `.json` — в документ Flecs. DATE — свой календарь: шапка дней недели, TODAY, сегодняшний день и выбранный день подсвечены, пустые клетки тусклые и не нажимаются. SDL календаря не даёт. SEND проверяет поля формы и пишет в строку `sent` или первую ошибку.

Редактор цвета ближе к пикеру Unreal: колесо hue/sat, вертикальная яркость, образец на клетке, ползунки R G B A H S V с числовым вводом (RGB и A — 0–255, H — 0–360, S и V — 0–100) и hex `#RRGGBBAA`. Альфа всегда в цвете; непрозрачный цвет — это альфа 255. Кнопки ALPHA больше нет. PICK включает пипетку: меню прячется, курсор становится крестом, следующий клик берёт цвет верхнего виджета окна (колесо и яркость считаются так же, как в шейдере). MENU — панель у кнопки, WINDOW — третье окно SDL. Цвет общий в `ColorBook`.

`assets/ui/sample.json` собирается в страницу INPUT (`uiImportJson` / `uiImportJsonFile`). У узла с полем `id` появляются компонент `UiName`, имя Flecs и symbol. `canvasFind(canvas, "json_note")` возвращает слот, код меняет подпись уже после импорта. Сейчас разбираются `id`, `role`, `dir`, `text`, `fill`, `w`, `h`, `grow`, `pad`, `gap`, `radius`, `tag`, `icon`, `children`. Роли: panel, button, label, field, check.

Отдельно от вёрстки есть документ данных. `jsonLoadFile` / `canvasLoadJsonDoc` читает JSON (до 1 МБ) в дерево Flecs: корень и дети с `JsonNode` (`ChildOf`), строки лежат в одном arena на `UiState`. Старт кладёт `assets/ui/sample.json` (32 узла). `jsonSaveFile` / `canvasSaveJsonDoc` пишет файл обратно. `jsonFind`, `jsonAt`, `jsonString`, `jsonNumber` читают узел. `jsonRelease` снимает дерево.

Картинки — `core/image/ImageFile.cpp`. Декод — stb_image 2 (PNG, JPEG, BMP, TGA, HDR, PSD, GIF). Сжатие — Intel ISPC Texture Compressor (`Libraries/ispc_texcomp`, `ispc` 1.31, цель AVX2): непрозрачная — BC1, с альфой — BC7 (профиль alpha fast; если формата нет — BC3), HDR — BC6H из half-float (профиль fast; иначе RGBA16F). Край дополняется до блока 4×4. У неподвижной картинки строится цепочка мипов, пока размер кратен 4; шейдер берёт мип по производной, шрифт по-прежнему читает уровень 0. GIF (до 16 кадров) складывается в одну текстуру без мипов, чтобы кадры не смешивались, задержка в миллисекундах. Heap каждого окна: 1 буфер, 9 картинок, 1 сэмплер. Слот 0 — SDF-шрифт, слоты 1–8 — фото (`gPhoto[8]`, флаг 32). Пустые слоты — серый блок BC1 4×4. Слот 0 по умолчанию — два кадра градиента 128×128, сложенные в текстуру 128×256 без мипов. `canvasLoadImage(canvas, slot, path)` заменяет текстуру. Виджет на INPUT: колесо зумит окно кадра, перетаскивание панорамирует, клик по миникарте прыгает в это место.

Текст — SDF FreeType со spread 2, порог узкий, чтобы буква не раздувалась. `textRun` кладёт строки в слот: лево, центр, право; верх, центр, низ; перенос по ширине; «...» в конце или в середине; подчёркивание и зачёркивание; интервал `leading`. Если слот ниже `em`, буквы уменьшаются. Обрезка «...» за один проход по ширине глифа. Подпись кнопки — ребёнок `Label`, номер в `labelOf`. Светлая заливка получает тёмный текст, тёмная — светлый. Выключенная подпись тускнеет вместе с кнопкой.

Заливка рисуется на весь бокс. Обводка — кольцо поверх края (`borderW`, флаг 64), бокс детей не сжимает. Тень — отдельный примитив (`shadow`, флаг 128) вокруг бокса. Прогресс — роль `Progress` и `UiRange`, дорожка без ползунка. Иконка из файла — `uiIcon` / `canvasIcon`: слот картинки `core/image`, без миникарты, клик проходит к родителю. Подсказка — `uiTip` / `uiTipAt`, панель с подписью. Полоса прокрутки рисует ползунок, когда содержимое выше окна, и тащится за него. Ребёнок кликается и рисуется только внутри боксов предков. Абсолютные координаты считаются от `uiContent` — бокс родителя минус padding. `addText` меняет размер только у подписи, не у кнопки.

Бокс — `UiFlex` целиком уходит в Yoga: направление и reverse, перенос, шесть выравниваний главной оси, align-items и align-content, align-self, basis, min/max, padding по сторонам, два gap, margin, static/relative/absolute, right/bottom, aspect-ratio, overflow, border-box и content-box. Список полей — `docs/widgets.md`. `drop`: 1 прячет последнего ребёнка, который не влезает в `minW`/`minH`, 2 — первого. Узел уходит из Yoga (`display: none`), соседи заново делят место. `canvasDock(panel, home, edges)` — биты лево/право/верх/низ. Пока панель тащат за шапку, над разрешённой стороной дома загорается зона; отпускание сажает панель в этот край. Сплиттер и кромка плавающего окна невидимы, пока курсор не на них; курсор становится resize. Плавающее окно с тегом -15 тянется за кромку и сворачивается кнопкой в шапке. `canvasOpenOs` открывает второе окно. Кадр ядра его поднимает по имени `tool`, холст наполняет `toolBuild`. Окно цвета — имя `color` и `colorBuild`. F5 = `canvasReload`.

Весь визуал собирается из виджетов ядра. Слайдер пишет число в `UiRange` и зовёт слушателей (`canvasListen`). Сам он не меняет превью и не красит страницу. Превью SCALE (высота, цвет, подпись `SCALE x.xx`) живёт в `Shell.cpp` и слушает виджеты `scale`, `preview`, `scale_text`. Ползунки цвета слушает сам редактор цвета. Кнопки проводника сами зовут `filesClick` через `uiBind`. Зоны инструментов, зума, поиска, чипов, крошек и боковой колонки берутся из боксов виджетов. Зум пишет одно число и в `FileLook.icon`, и в `UiRange`. Разделитель с тегом -5 тянет ширину предыдущего соседа в строке. Виджеты лежат по файлам: `Button`, `Field`, `Slider`, `Scroll`, `Splitter`, `Image`, `List`, `Menu`, дерево узла в `Tree`. Цвет и календарь — `core/ui/kit`.

Файловый менеджер — модуль `core/files`. Кадр его не знает: `filesAttach` отдаёт ввод, дорисовку сетки и фокус текста. Картинка из тех же кнопок, поля, слайдера, подписей и разделителя. Показ и скрытие окна — клики оболочки (`-94` / `-93`), не код виджета. Настройка снаружи: `filesStyle`, `filesGo`, `filesRoot`, `filesOnOpen`. Поиск и переименование — обычное поле: стирание идёт по символу UTF-8, не по байту. Клик мимо поля или Enter сохраняет имя. Слева FAVORITES и FOLDERS, ширина тянется разделителем. Путь — кнопки `имя > имя`. Сетка файлов — те же кнопки, до 18 видимых, в памяти до 256 имён. Вид сетки стоит `relative`, поэтому абсолютные клетки считаются от панели, а не от плавающего окна. Снизу: под курсором `имя.ext (EXT, размер)`, несколько — `N selected (размер)`. Двойной клик открывает только тот же объект. Меню — обычное контекстное меню ядра. Назад выше корня не пускает. Демо на открытие картинки вызывает `canvasLoadImage`.

Демо — страница INPUT: NAME, EMAIL, TEL, URL, READONLY, PAD / COLOR, PASSWORD, FILE, DATE, COLOR, кнопки FILE / DATE / COLOR / SEND, виджет IMAGE с миникартой, checkbox, radio и карточка из `assets/ui/sample.json`. Подпись `json_note` после импорта заменяется из `shellBuild` на `named in flecs`. FILE больше не рисует свой список каталога. Поверх кадра — окно FILES.

Тема — POD `UiLook`. Наведение и меню идут через `UiAnim`. Двойной клик по шапке разворачивает окно. Окно без рамки, края ресайзят, строки SCENE перетаскиваются.

Шейдер `core/ui/ui.slang` → SPIR-V 1.6, vertex + fragment.

## Как устроен кадр

```
hostTick → windowsPump → InputFrame
FrameDesc → present (vsync / mailbox / immediate)
команды окна (minimize, диалог, курсор) применяет core/host
Flecs/Yoga: layout если dirty, hit-test, правка колонок
грязные примитивы → mapped SSBO → flush
descriptor heap bind → один draw → present_wait
```

Модули `render` и `gpu_scene` (visbuffer, shade, SSR) собираются, в этот exe не линкуются.

## Как делать дальше

Перед кодом: прочитать этот файл, `docs/widgets.md` и, если правка похожа на прошлую ошибку, `docs/mistakes.md`. Ответить: это уже есть, какой слой владеет, какой один кусок отсутствует.

Новый кусок — только эта дырка. Остальное — вызов слоя ниже. Виджет рисует себя и отдаёт событие. Что событие значит, пишется там, где виджет создают: `uiBind`, `uiDrag`, `uiEdit`, `canvasListen`, `canvasOnFocus`. Строка — сущность `uiTextId`, стиль на ней, байты через `uiText` хозяина.

Папка решает границу. Ядро не включает демо, движок и `old`. Экран — дерево уже существующих виджетов плюс одна функция. Второй текст, вторая кнопка, второй декодер и второй обход диска не пишутся.

После правки живого кадра в том же заходе обновляют `docs/now.md` и `docs/widgets.md`. Если форма была неверной, сначала строка в `docs/mistakes.md`: что сделано, почему так нельзя, какая форма вместо этого.
